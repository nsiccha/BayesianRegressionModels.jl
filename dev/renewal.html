Epidemic renewal and reporting delays ​

This example uses 56 simulated days of epidemic counts, generated with seed

  1. The generating reproduction number starts at 1.3 and follows a daily

log random walk. A gamma generation interval links past infections to new infections; a lognormal reporting delay separates infection from observation. Daily reports follow a negative-binomial distribution. Simulation makes the expected report trajectory available for comparison, while the fit receives only the counts, observation days and fixed delay distributions. There are no patient records in this example.

Model ​

The renewal equation separates transmission from observation. Infectiousness is a weighted sum of previous incidence, and the reproduction number scales that sum to give today's infections. Reports are a second convolution:

It=Rt∑s≥1gsIt−s,mt=∑d≥0hdIt−d,Yt∼NegBinomial2(mt,κ−2).

The generation-interval weights g start at lag one; reporting-delay weights h include lag zero. The distinction matters: same-day reports are possible, but an infection does not generate itself. The expected-case function carries the infection history through both convolutions. Before day one, the model uses an exponential history whose initial growth rate satisfies the discretized Euler–Lotka equation for the initial reproduction number.

julia
    expected_cases(log_R::vector[T], log_I0::real, gen_pmf::vector[G], delay_pmf::vector[D])::vector[T] = begin
        I0 = exp(log_I0)
        r0 = growth_rate(exp(log_R[1]), gen_pmf)
        I::vector[T]
        for t in 1:T
            I[t] = clamp2(exp(log_R[t]) * lagged_sum(I, t, gen_pmf, I0, r0, 1), 0.0, 1e15)
        end
        Y::vector[T]
        for t in 1:T
            Y[t] = lagged_sum(I, t, delay_pmf, I0, r0, 0)
        end
        Y
    end
    # ── observation family: negative-binomial counts on the rows marked observed ──
    # cases ~ NegBin(mean Y, variance Y + cluster^2 Y^2); a row with observed == 0 is not scored,
    # and the generator draws every row, so an unobserved row's draw is its forecast

BRM's rw(time) term supplies the daily innovations. The intercept prior sets the first log reproduction number; the term's SD prior sets the scale of changes from one day to the next. log_I0 determines the initial infection scale. cluster is a positive overdispersion scale: the observation variance is m + cluster² m². These quantities are inferred jointly, so uncertainty in initial incidence propagates through the entire reporting trajectory.

julia
function renewal_single_model(data = renewal_single_data())
    @brm data begin
        log_I0  ~ Normal(log(50.0), 0.5)                    # log initial infections (scale of the seeded history)
        cluster ~ Normal(0.0, 0.1; lower=0.0)               # overdispersion of the counts
        log_R   ~ 1 + rw(time)                              # log R_t: a random walk over days
        effect(log_R, Intercept) ~ Normal(log(1.3), 0.1)    # ... its first value, log R_1
        sd(:, rw(time)) ~ Normal(0.0, 0.05)                 # ... its daily innovation scale
        Y       = expected_cases(log_R, log_I0, gen_pmf, delay_pmf)
        cases   ~ nb_cases(Y, cluster, observed)
    end
end

functions {
matrix hcat(vector x) {
    int n = dims(x)[1];
    return to_matrix(x, n, 1);
}
vector random_walk_rows(
    real sigma,
    vector z,
    array[] int idx
) {
    int N = dims(idx)[1];
    vector[(dims(z)[1] + 1)] x = random_walk_path(sigma, z);
    vector[N] out;
    for(i in 1:N) {
        out[i] = x[idx[i]];
    }
    return out;
}
vector random_walk_path(
    real sigma,
    vector z
) {
    int n = dims(z)[1];
    return append_row(0.0, (sigma * cumulative_sum(z)));
}
vector expected_cases(
    vector log_R,
    real log_I0,
    vector gen_pmf,
    vector delay_pmf
) {
    int T = dims(log_R)[1];
    real I0 = exp(log_I0);
    real r0 = growth_rate(exp(log_R[1]), gen_pmf);
    vector[T] I;
    for(t in 1:T) {
        I[t] = clamp2((exp(log_R[t]) * lagged_sum(I, t, gen_pmf, I0, r0, 1)), 0.0, 1.0e15);
    }
    vector[T] Y;
    for(t in 1:T) {
        Y[t] = lagged_sum(I, t, delay_pmf, I0, r0, 0);
    }
    return Y;
}
real growth_rate(
    real R,
    vector gen_pmf
) {
    int G = dims(gen_pmf)[1];
    real r = 0.0;
    for(iter in 1:2) {
        real f = (-1.0 / R);
        real df = 0.0;
        for(s in 1:G) {
            f += (gen_pmf[s] * exp(((-r) * s)));
            df -= (s * gen_pmf[s] * exp(((-r) * s)));
        }
        r = (r - (f / df));
    }
    return clamp2(r, -2.0, 2.0);
}
real clamp2(real x, real lo, real hi) {
    return ((x < lo) ? lo : ((x > hi) ? hi : x));
}
real lagged_sum(
    vector x,
    int t,
    vector pmf,
    real x0,
    real r,
    int first_lag
) {
    int G = dims(pmf)[1];
    real acc = 0.0;
    for(i in 1:G) {
        int s = (t - ((first_lag + i) - 1));
        acc += (pmf[i] * ((s >= 1) ? x[s] : (x0 * exp((r * (s - 1))))));
    }
    return acc;
}

The observed mask in the custom count family distinguishes observed from unobserved days. This fit observes all 56 days. Setting later entries to zero removes those likelihood contributions while retaining the latent process and predictive outputs for those days. It does not set their counts to zero or treat missing reports as evidence of no infections. A forecast must therefore be constructed by changing the mask, not by appending zero counts to the fitted observation vector.

Delay distributions ​

A continuous delay is not rounded independently of the primary event time. An infection occurs somewhere within its calendar day. The data preparation integrates over a uniform within-day offset before assigning probability to successive report days, then normalizes over the chosen support. The probability vectors enter the model as data, so another generation interval or reporting-delay distribution changes the fit without changing the model body. This example conditions on those distributions; their uncertainty is not included in the posterior bands.

A line list would require a separate delay likelihood. If both event dates are recorded as intervals and recent events are missing long delays, BRM's double_interval_censored family integrates the primary event window and conditions on the observation cutoff. The epidist research example contains that model and its comparison with epidist. Estimating delays from such a list is a different inferential step from fitting counts with fixed delay weights; the research notes describe how the two relate.

Reporting delays spread the effect of a change in transmission over later days; the plot should be read as a trajectory of reports, not of infection onset. The random-walk prior regularizes changes that the delayed counts cannot identify individually.

Commands and fit receipt

The repository's test environment supplies the pinned BRM, StanBlocks, BridgeStan, WarmupHMC and TreeArrays dependencies. These shell commands are manual: the docs build executes the model declarations and figures but reads the completed fit's summaries. Run the fit deliberately when its model, data or settings change; routine documentation edits reuse the cache.

sh
julia --startup-file=no --project=test test/setup_env.jl
julia -t 4 --startup-file=no --project=test research/epi_renewal/fit.jl

The script writes its receipt before sampling and saves the draws outside the repository. Its key includes the emitted program, data, settings, seed and sampling harness. TreeArrays reduces the named chain and draw axes to small summary tables. A second invocation with the same key rebuilds those tables from the saved draws. The receipt identifies the program behind these numbers.

On a fresh checkout the draws may be absent. An existing receipt guards against repeating a recent fit; set BRM_DOCS_FIT_FORCE=1 for a deliberate rerun. BRM_DOCS_CACHE selects a persistent draw-cache directory; its default is under the system temporary directory. Only the small summary tables belong in git.
