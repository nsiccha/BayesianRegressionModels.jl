A Python/JAX module ​

jax_source writes a Python module from an RKBRMI. The module evaluates the model's log density and constrained parameters with JAX; NumPyro or BlackJAX can sample it without a Julia process. This example fits a varying-intercepts, varying-slopes regression in Julia and Python, then compares the gradients and posterior distributions.

Model ​

Each group has its own intercept and slope around a population line. Their deviations share a correlation parameter; the observation noise has one residual standard deviation. The data are synthetic.

brm-comparison
Correlated group intercepts and slopes
julia
function varying_slopes_model(data = varying_slopes_data().data)
    (@brm begin
        "Residual scale of the response."
        sigma ~ Exponential(1)
        "Expected response: a population line, and each group's own intercept and slope, correlated."
        mu ~ 1 + x + (1 + x | g)
        effect(mu, Intercept) ~ Normal(0, 2)
        effect(mu, x) ~ Normal(0, 1)
        sd(mu, g) ~ Exponential(1)
        "Measured response."
        y ~ Normal(mu, sigma)
    end)(data)
end

Data preparation ​

Pass exactly the columns listed by model.DATA, by name. The native binding returned by rk_bound_data(rk) can contain extra intermediate values; those are not keyword arguments of prepare_data.

The Python environment is separate from the documentation build. The reproduction script executes this workflow; the tables below read its cached results.

python
import jax
jax.config.update("jax_enable_x64", True)
import jax.numpy as jnp
import model as m

# inputs: the Julia binding transferred to Python arrays and label lists
prepared = m.prepare_data(**{name: inputs[name] for name in m.DATA})
u = jnp.zeros(m.dimension(prepared), dtype=jnp.float64)
log_density = jax.jit(m.log_density)
value = log_density(u, **prepared)
gradient = jax.grad(lambda u: m.log_density(u, **prepared))(u)
expected_response = m.constrain(u, **prepared)["mu"]

Enable 64-bit values before creating the JAX arrays to match Julia's Float64 calculation. PREPARED describes the data accepted by the density functions. JIT compilation can reuse an executable when the new prepared inputs have the same shapes and static shape-setting values; changing the number of groups changes the parameter dimension.

UNTRANSLATED identifies data-only definitions that still need values from Julia. Exporting those values allows Python inference to run independently; preparing arbitrary new raw data entirely in Python requires an empty UNTRANSLATED mapping.

Posterior sampling ​

NumPyro's NUTS sampler accepts the negative log density as its potential_fn. This uses the exported density directly, including its coordinate Jacobian.

Sampling runs only in the reproduction environment and is cached, so this block is not rerun during the documentation build.

python
import numpy as np
from numpyro.infer import MCMC, NUTS

potential = lambda u: -m.log_density(u, **prepared)
sampler = MCMC(NUTS(potential_fn=potential, target_accept_prob=0.8),
               num_warmup=1000, num_samples=1000, num_chains=4,
               chain_method="sequential", progress_bar=False)
initial = jnp.asarray(0.1 * np.random.default_rng(7).standard_normal(
    (4, m.dimension(prepared))))
sampler.run(jax.random.PRNGKey(7), init_params=initial)
draws = sampler.get_samples(group_by_chain=True)

The native fit uses rk_logdensity_problem and WarmupHMC's completion_warmup_mcmc, requesting four chains with a completion quorum of three. It runs with one Julia thread because concurrent RK/Enzyme gradients are currently unsupported. NumPyro starts independently near zero in unconstrained space. The two samplers have different warmup procedures; the timings depend on those procedures and the host load. Stopping after a quorum selects chains by completion time, which can bias a posterior if runtime depends on the sampled region. The diagnostics below do not rule out that selection effect.

New designs ​

Use reprocess to keep fitted preprocessing when changing the design:

julia
training = varying_slopes_data().data
new_data = merge(training, (; x=training.x .+ 0.5))
replay = reprocess(rk, new_data)
replay_source = jax_source(replay.model, rk_bound_plan(replay); values=(:mu,))
replay_inputs = rk_bound_data(replay)

The replay binds 320 predictor values.

A saved fitted state can also reconstruct a replay without the training rows: RKBRMI(builder(new_data), brm_fitted_state(rk)), where builder is the original data-free BRM builder. Apply the same DATA filter in Python. A replay that omits a response needed by log_density is refused with a ContractValidationError; retaining that response and requesting values is different from exporting a response-free predictive program.
