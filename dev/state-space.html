Continuous-time latent states ​

The data are 40 synthetic measurements at irregular times over a period of several weeks. A latent Ornstein–Uhlenbeck process fluctuates around a stationary mean; independent Gaussian measurement error separates the observations from that process. The simulation uses seed 144 and retains the generating states for comparison. Time is measured in days, and the response is in arbitrary units. The fit sees the observation times and measurements; the generating states are used only to assess and display the result.

Continuous-time model ​

The process returns towards its mean at a positive rate. Its stochastic differential equation can be written in terms of the stationary standard deviation, rather than the diffusion coefficient:

dXt=λ(μ−Xt)dt+2λsdWt,Yj∼Normal(Xtj,σ).

The exact transition over a gap of length dt has persistence exp(-rate * dt) and innovation standard deviation stationary_sd * sqrt(1 - exp(-2rate * dt)). Small gaps retain most of the previous state; long gaps approach the stationary distribution. The first state is drawn from that stationary distribution. This is a substantive initial-condition assumption, not an estimate of a pre-observation path.

The same transition is used to simulate the data and to construct the fitted path. No numerical integration grid is introduced, and there is no Euler discretization error for this model. expm1 evaluates the innovation variance accurately when time gaps are small.

julia
StanBlocks.@deffun begin
    ou_path(dt::vector[n], z::vector[n], mu::real, rate::real, stationary_sd::real)::vector[n] = begin
        x::vector[n]
        x[1] = mu + stationary_sd * z[1]
        for j in 2:n
            persistence = exp(-rate * dt[j])
            innovation_sd = stationary_sd * sqrt(-expm1(-2.0 * rate * dt[j]))
            x[j] = mu + persistence * (x[j - 1] - mu) + innovation_sd * z[j]
        end
        x
    end
end

Sampled states ​

The declaration samples independent standard-normal innovations z and constructs the latent state as a deterministic function of those innovations and the population parameters. This is a non-centred representation of the Gaussian path. BRM exposes state as a named derived output, so posterior summaries use its public descriptor address without identifying generated Stan coordinates by hand.

function state_space_model(data=state_space_data())
    @brm data begin
        mu ~ Normal(0.0, 1.0)
        rate ~ LogNormal(log(0.8), 0.5)
        stationary_sd ~ LogNormal(log(0.6), 0.5)
        sigma ~ LogNormal(log(0.15), 0.4)
        z[1:n] .~ Normal.(0.0, 1.0)
        state = ou_path(dt, z, mu, rate, stationary_sd)
        y ~ Normal(state, sigma)
    end
end

functions {
vector ou_path(
    vector dt,
    vector z,
    real mu,
    real rate,
    real stationary_sd
) {
    int n = dims(dt)[1];
    if (dims(z)[1] != n) reject("ou_path: dim mismatch — `z` dim 1 (= ", dims(z)[1], ") does not match `n` (= ", n, "), inferred from `dt` dim 1. `n` sizes: `dt` dim 1 (= ", dims(dt)[1], "), `z` dim 1 (= ", dims(z)[1], ").");
    vector[n] x;
    x[1] = (mu + (stationary_sd * z[1]));
    for(j in 2:n) {
        real persistence = exp(((-rate) * dt[j]));
        real innovation_sd = (stationary_sd * sqrt((-expm1((-2.0 * rate * dt[j])))));
        x[j] = (mu + (persistence * (x[(j - 1)] - mu)) + (innovation_sd * z[j]));
    }
    return x;
}

    vector x1,
    vector x2,

    }
    return rv;
}

The mean has a normal prior. The reversion rate, stationary process SD and measurement SD have lognormal priors on positive values. The prior on the rate is centred around a response to changes over a few days; the prior on measurement noise reflects the intended scale of the synthetic example. These values are visible in the declaration and are part of this model, not defaults supplied by BRM.

Stationary process variation and measurement error affect the data differently. Process variation is correlated across nearby observations, whereas measurement errors are independent. Irregular gaps help express that difference, although a short series may still leave the two scales weakly separated. The fitted state between observations is not part of this output: only states at the supplied times are sampled. Adding a plotting grid requires conditional path recovery or additional latent times, rather than interpreting straight line segments as posterior draws of a continuous path.

Fit and diagnostics ​

Four independent WarmupHMC chains start from different random seeds, each requesting 1,000 retained draws. The completion sampler requires three chains to finish and then lets the remaining chain finish its current warmup round. The table records how many chains contributed, which were omitted, the total retained draws, divergences and sampling time. These are results of the cached run; rebuilding this page reads its tables without sampling again.

The blue intervals describe uncertainty in the latent state after conditioning on the entire series. They are smoothing intervals: later observations can inform an earlier state through the process model. A filtering interval would instead condition only on observations available up to that time. The distinction matters when using a fitted trajectory for retrospective interpretation versus real-time monitoring.

Orange points include measurement noise, so their position outside a state interval is not itself a predictive failure. The script also writes posterior predictive quantiles for a new measurement at each supplied time. Those intervals include both state uncertainty and observation noise and are wider for that reason. The generating path is retained in the trajectory table, allowing a simulation check without treating it as observed data.

Marginalized states ​

For this linear Gaussian process, a Kalman filter can integrate the latent path out of the likelihood exactly. HMC then needs only the population parameters, followed by conditional state recovery. The filters guide explains that likelihood representation and the boundary between exact Gaussian filtering and approximations for nonlinear or non-Gaussian models. The sampled version here keeps the state construction explicit and provides a direct example of posterior state summaries. It is not a claim that sampling every state is preferable for long series.

The earlier multivariate continuous-time examples, including hierarchical stress and mood models and approximate filters, remain in the research directory. They add scientific structure and numerical questions beyond the single exact transition taught here.

Reproduce ​

Commands and fit receipt

The repository's test environment supplies the pinned BRM, StanBlocks, BridgeStan, WarmupHMC and TreeArrays dependencies. These shell commands are manual: the docs build executes the model declarations and figures but reads the completed fit's summaries. Run the fit deliberately when its model, data or settings change; routine documentation edits reuse the cache.

sh
julia --startup-file=no --project=test test/setup_env.jl
julia -t 4 --startup-file=no --project=test research/ema_ctsem/fit.jl

The script writes its receipt before sampling and saves the draws outside the repository. Its key includes the emitted program, data, settings, seed and sampling harness. TreeArrays reduces the named chain and draw axes to small summary tables. A second invocation with the same key rebuilds those tables from the saved draws. The receipt identifies the program behind these numbers.

On a fresh checkout the draws may be absent. An existing receipt guards against repeating a recent fit; set BRM_DOCS_FIT_FORCE=1 for a deliberate rerun. BRM_DOCS_CACHE selects a persistent draw-cache directory; its default is under the system temporary directory. Only the small summary tables belong in git.
